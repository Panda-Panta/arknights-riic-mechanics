# 心情、轮班与长期日产出

当前应用的既有原生排班路径使用2026-10-03 Mower alpha `b2d9ac85fe070e805aadf0d5f44fc095c1e95253` 决策，回收站新增扩展固定到2026-10-12 alpha `9091f2b6b4da2a2fb66c47881a47b82dc0885ad7`。Free/VIP、逐宿舍恢复、菲亚交换和有序多候选已进入模拟；完整预演、过程锁及验证边界见本文件末尾2026-10-04节。下列标为历史的旧源码、零操作耗时、固定床池和实体跑单记录用于追溯，不能作为当前默认路径说明。总体覆盖见 [coverage.md](coverage.md)。

## 心情

心情范围0–24。工作基础消耗1/小时；制造/贸易1/2/3名入驻者的设施基础减免0/0.05/0.1。每名有效工作中枢干员提供0.05基础减免，只计一次，不把UI两个读数重复叠加。自身、同站其他人、同站全体、跨站全体的技能修正分别处理；中枢对自己与对其他设施的特殊比较规则另看具体技能。

心情恢复并非全部负消耗直接相加：需要处理同类最高、消耗清除（槐琥等）、全员减免、维什戴尔/魔王特殊比较、玛恩纳的暖机延长等。规则按时间与心情阈值重新求值，负消耗可以表现为恢复，最终心情不能超过24。

宿舍原始基础恢复为1.6/1.7/1.8/1.9/2.0点每小时；氛围加成及后勤恢复另加。当前原生排班路径按实际房间等级、氛围、在住人员、单体目标及同类最高逐时间片求值，菲亚梅塔固定2/h并排除其他来源。氛围或单体目标的缺省策略要明示；默认目标选择是软件策略，尚未证明游戏随机选靶机制。旧一对一引擎的2/2.5/3/3.5/4平均休息近似只适用于兼容结果，不能替代当前逐宿舍模型。

0心情者的工作技能通常失效，但“已进驻”的存在性触发须独立判断，尤其森蚺与Lancet-2；不能把人删除后再计算存在性条件。

### 常驻策略与状态分离

`zeroMoraleOperatorIds` 表示当前心情状态；`workaholicOperatorIds` 表示允许心情归零后继续占岗的排班策略。初始心情为0不会自动成为常驻策略。旧兼容引擎可以独立保留明确常驻者；原生 Mower 路径中，工作狂不独立发起普通休息、不预约恢复床，但仍参加整组候补选择和工作岗切换，需满足该组合法替班条件。归零后的工作技能与“已进驻”存在性分别判断，按实际占位重算联动。

异格判定优先读取原始 `isSpChar`（目录/运行时 `isAlter`），再按技能及术语名单处理例外。名称迁移时从不可变源记录保留身份信息，业务层以正式代号查询；旧ID识别仅作显式迁移依据，不能对中文代号运行原始ID正则，也不能把ID编码视为永久规则。

## 组合与替补

同组合允许跨设施共同下班、上班。先完整选择候补、预约床位并原子提交决策；多房间物理安排仍可分步执行，过程锁抑制中间占位引起的副表重入与纠错，不把实际操作时段抹成零。生产积分与全局资源按该时段实际占位重算。主力/替补不能实体重复占岗；理想跑单候选与菲亚交换目标只是引用，可出现在多处列表。没有合法候补/床位时报告阻塞或按该路径明示空岗，不能凭空补员。

Mower 的 Free、Current 是岗位语义，不是干员名字。replacement有顺序，不能在无提示时丢弃后续候选。workaholic是排班策略，不等于把每名策略成员初始心情设0；逗号列表需要逐个拆分。导入保留无法理解的字段，不执行其内容。

### Mower 宿舍语义

- 已明确配置在宿舍岗位中的干员是宿管或特殊技能执行者。普通宿管不需要替补，不能因其 `replacement` 为空而把有效排班标成不完整。
- `Free` 表示可供工作设施疲劳干员使用的动态休息位，不是干员名字或普通非法空席。当前事件模型按容量、VIP/普通顺序和选定 alpha 决策选择进入者；物理Free槽与有效恢复床池须区分。
- Mower 把每个宿舍枚举到的第一个 `Free` 作为 VIP 位，其余 `Free` 为普通床位；低休息优先级通常先用普通床，必要时才回退 VIP 位。适配器必须按宿舍分别标记，不能把全部 Free 统一为同一优先级。
- 菲亚梅塔的宿舍 `replacement` 列表表示心情交换目标候选，不是离岗后的普通接班人。候选可以同时是制造站、贸易站或中枢的当前主力，因此不能套用“替补不得为在岗主力”的普通冲突校验。
- 菲亚梅塔的“患难之交”只有在宿舍内且自身满心情时才交换心情；Mower 的候选列表负责表达允许交换的对象与顺序。当前原生路径已执行交换事件，按候选顺序及阈值重选；只提供旧兼容引擎的入口仍须保留原列表并报告无法执行的范围，不能压成一个普通轮班替补。
- 交换不是单向治疗：目标交换后为 24，菲亚梅塔获得目标交换前心情 `m`；菲亚梅塔在宿舍固定按 `2/h` 恢复并排除其他恢复来源，因此下一次满心情所需时间为 `(24-m)/2` 小时。目标按候选顺序结合心情阈值、组内相对下限、暖机和休息状态重新筛选，不是固定归零、固定 12 小时、循环轮询或无条件选择最低心情。
- Mower 全局菲亚阈值默认 90%：开启防呆时固定使用 90%，自定义值无效；关闭防呆时先按候选顺序选择不高于自定义阈值的目标，均不符合时改选心情最低者。急救阈值默认 75%，当整体平均心情不高于「休息阈值 × 急救阈值」时，普通休息规划不再按高优人数限制理想床位数。孑的精 0 跑单选项属于每次计算的产出配置。

旧一对一轮班引擎的兼容投影只覆盖其能表达的生产设施/中枢接班关系。宿舍、右侧设施及菲亚梅塔交换目标留在 Mower 工作区模型中；它们不应写入旧 `operatorBackups`。原始列表与投影必须分离，确保导入、编辑、导出不会因计算兼容而丢失信息。

旧兼容引擎在无法执行动态休息池时，可把每个非`empty`床位作为稳态占用近似，用于“宿舍在住人数”类全局资源，并标注该假设。当前事件路径按时间片读取实际占用，不能永久固定为20。

## 长期日均

用户目标是稳定长期产出的每日平均，不是初始满心情第一天。先暖机，再采样；报告实际窗口、随机种子及收敛检查。主工作台当前默认3天预热+7天采样；其他搜索/调试入口与旧兼容引擎可有不同窗口（旧calculate路径30+90），以本次输入为准。任一固定窗口完成都不等于长期收敛证明。

精确算法使用下一事件：心情阈值/疲劳、休息结束、订单生成/完成/交付、制造完成/领取、无人机生成/使用、定时跑单等。每段推进实际时长，累计产物，最终除以采样天数。暖机技能在离站后是否重置依原始技能确认，不能无条件永远取暖机上限。

## 资源守恒与收益口径

分别报告经验值、赤金件数及库存估值、订单龙门币、源石碎片、合成玉；赤金价值与卖出龙门币是同一资源流的不同阶段，不能直接相加称作净收入。

- 赤金净变化=制造+外部补给−订单交付。
- 碎片净变化=制造−源石订单消耗。
- 龙门币净流入=订单收入−制造/其他加工成本。
- 材料消耗按配方逐项列出。有限资源模式在缺料时阻塞相应生产/贸易；默认潜力模式允许无限材料，需作为假设单列，不按有限库存运营或净利润解读。
- EXP与龙门币保持独立单位，换算价值必须给用户选择的汇率。

旧静态/兼容收益字段口径：`netGoldCount = goldCount - goldConsumed`，`netGoldValue = netGoldCount × 500`，`totalEquivalentLmd = orderLmd + netGoldValue`。该估值可为负，且不含EXP或完整配方成本。当前事件报告还应分别读取资源账本的开闭余额、流入/流出、待领取产物和采样期已完成产出；默认82或自定义加权分是评分，不是完整净利润。增加外部补给时另列来源，避免库存估值与卖出收入重复记账。

无人机要维护持有量、溢出及使用策略；将每日充能全数立即使用是“无溢出”的理想假设。只有该假设成立时，产量公式直接加日充能×3分钟才可靠。

Mower 排班 JSON 通常不表达本软件的 `droneTarget`。导入后若回退为 `none`，报告可以列出每日生成的无人机，但任何产线的 `droneExtra` 都会是 0。与人工表格对照时必须检查表格是否把无人机全投向某种产品，并把这项与轮班/技能差异分开；例如 `252二赤金 (Test)` 的 C54 被加入 D14，明确把无人机价值计入赤金。

人工表格中的“工作占比”是外部假设，不应从 Mower JSON 臆造。先确认占比是固定填写、由时刻表推导还是由事件模拟得到；固定 80%/20% 与旧引擎基于心情、唯一替补和近似恢复求出的长期占比不是同一口径。表格可作为公式已核实的外部基准，但只有当排班事件、无人机目标、库存和取货策略也一致时，才可升级为精确数值 oracle。

当前 `productionTimeline` 与 `resourceLedger` 已有订单/制造队列、逐单快照、领取、无人机库存及有限资源配方成本的专项回归；默认潜力计算使用无限材料。模块回归不证明任意排班库存闭环或真实游戏时序，长期收敛、全部技能及功能设施任务仍按 coverage.md 保留边界。

## 回收站与 v078 干员（2026-10-12）

新技能的数据阶段与条件见 [new-operators-v078.md](new-operators-v078.md)，设施常数见 [facilities.md](facilities.md)。回收站使用独立计时模块记录转化进度、仓库、收取和满仓停机；调度系统负责实际进驻、心情和替补。两者通过当前时间片有效工作状态连接，转化件数作为独立报告字段。

回收站不是普通制造配方：基础100%效率每件48小时，无人进驻也继续；1/2/3级容量为5/10/10，满仓停止推进且保留未完成进度。换班、技能阶段或心情失效引起效率变化时，已完成的基础工作量保留。采样起点只归零采样计数，暖机期间的仓库和进度继续存在。报告区分本次窗口完成件数、领取件数、待领取件数、剩余进度和满仓时长。

原生 `recycle` 采用普通工作设施的主表、组合、有序替补、副表和显式任务语义。缺省条目不补建；1级按实际容量1限制进驻，2/3级按2限制。旧工作区把 `recycle` 保存为未知房间时，迁移应保留其驻员、替补、组合及原生未知字段。回收站工作人员进入相应“基建内工作/存在/设施等级”计数，身份、明确术语名单和0心情存在性仍分别判定，不能把他们无条件加入每种派系联动。

Mower alpha 该版回收收取要求待办出现回收图标与收取角标，沿用十五分钟门槛，并复用物资奖励页关闭。软件数值适配以待领取件数模拟该提示，再记录一次收取事件；不执行图像识别或真实设备点击。未建回收站的旧夹具保留原固定版本的通知边界，回收站扩展单独验证新边界。

材料随机种类、稀有度分布和市场价值尚未模拟，材料件数不参与82评分或龙门币净流入。界面 +50% 提效选择只计算固定条件的效率预览；事件模拟目前不投料，也不消耗或创建提效材料。有限投料时长、自动投料以及真实收取识别需要各自的实现与证据。

Mower 该版图片改为14个QR码，完整压缩排班内容保持不变，给右侧回收站卡片留出空间。本软件导出14码并兼容14/16码导入；解压校验必须成功，旧16码图片只识别出14份时应继续扫描，不能因码数达到14就接受缺失排班。格式往返与数值联动验证分开记录。

## 实际练度技能选择（2026-09-19）

动态模拟已支持逐干员精英阶段与等级。导入干员库后，按每个技能槽选择已解锁的最高版本，构建本次计算专用快照；禁止修改共享满技能目录，也不能把低练度自动提升为满培养。制造、贸易、中枢联动、心情、宿舍恢复、订单容量和跑单奖励均读取该快照。未解锁技能不生效；仍未量化的规则保留诊断。

实际练度不同于最高技能不再触发 INVENTORY_SKILL_STAGE_UNSUPPORTED。未持有干员、非法练度和实际排班错误仍应阻断。静态组合目录的满技能证据校验与动态模拟准入分开，不能把静态模板的限制重新施加到动态模拟。

理想跑单的但书、龙舌兰使用各自当前已解锁版本；低级技能可以跑单，但不得套用高级奖励。收益转换仅接受排班模拟和生产模拟均完成的报告；未完成报告保留日志并显示原因，不显示成功的零产出。实现见 src/simulator/productionTimeline.ts 与 src/scheduler/rosterRuntime.ts。


## Mower 副表动态适配（2026-09-22，历史基线）

以下记录对应当时零额外操作耗时的适配版本。Current/副表数据语义继续保留；当前执行已接入原版显式等待和选定 alpha 的完整预演，不能沿用本节的旧执行边界解释当前应用。

导入的 backup_plans 由 src/scheduler/backupPlans.ts 编译和执行。按源码数组顺序叠加非 Current 计划槽位；策略列表有序去重合并；取消激活从主表重建。Current 计划保留前层槽位，Current 任务保留当时实际人员，但显式移动同一人会腾空其原位。任务仅在激活沿执行。时机按 BEGINNING/BEFORE_PLANNING/AFTER_PLANNING/END 的门槛判断。

副表覆盖不能重置心情、时间、生产账本或将人复制到多个岗位。显式任务挤出休息人员时保留心情并候床，不创造床位；恢复截止时间必须覆盖全组成员。free_blacklist 过滤空闲填床，不禁止显式宿舍任务。

条件解释器按本地 Mower logic_expression.py 的括号拼接语义，支持条件树及字段内文本表达式、数字/布尔/None、and/or/not、比较与链式比较、四则运算、is_working/is_resting/current_mood/current_room；例如 operator 为 >4 且右值为空时等价于 > 4，空条件不触发。按用户 2026-09-22 指令，包含 op_data.party_time 的整张副表跳过并输出 BACKUP_EXTERNAL_CONDITION_SKIPPED，不执行该副表岗位/策略/任务，也不把外部谓词改成 True；原始导入导出数据保留。其他未知生产条件仍阻断，不扩大为任意表达式执行。本实现是零操作耗时模拟器内的副表适配，不等于 Mower 的设备任务/时间/识别行为复刻。

自动生成禁止副表：smartRoster、automaticRoster、molecularSynthesis、rosterDraft 在私有副本去掉副表；评分入口拒绝副表，最终输出再检查。普通 replacement 候补仍属于主表；原始导入工作区保持不变。

验收采用 validation/mower-backup-2026-09-22 中的原图与解码排班。九表逐项触发/未触发、重叠恢复、输入不变和24/168小时运行分层验证；成功跑完不能据此声称与截图工休比、订单分布、收益精确一致。

## Mower 图片长期对照补充（2026-09-22，历史）

Mower RecordPie.vue 的工休比按相邻心情观测差分估计：下降或不变算工作，上升算休息；菲亚梅塔饼图固定全休。此值不能与模拟器非疲劳工作占比直接等同。新日志 Mower 报表对照独立展示龙舌兰额外价值，不增加物理赤金库存，不改变自动生成评分合同。

默认单体恢复目标按槽位挑选可接受外部恢复的未满干员，跳过菲亚梅塔；显式目标仍可覆盖。这仍是模拟目标策略，并非对游戏随机选靶机制的确认。副表把常驻干员移入动态床位后，不应为其建立空的普通返岗分组。
